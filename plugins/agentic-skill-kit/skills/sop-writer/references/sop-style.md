# SOP Writing Style

## Step wording
| ❌ Rough input | ✅ SOP step | Expected result |
|---|---|---|
| "then save it" | Click **Save**. | Message "Record saved" appears. (or TBD) |
| "enter awb and pcs wt" | Enter **AWB No.**, **Pieces** and **Weight**. | Fields accept values; no error. |
| "check if DG, if yes send to DG team" | Verify the **DG** flag. If **Yes**, go to step 9; else continue. | Flag visible on booking. |
| "wait for it to go" | Wait for status **Sent**. | Status changes to **Sent** within TBD min. |

## Verbs
Click · Select · Enter · Upload · Verify · Confirm · Wait for · Print · Send · Log out.
Avoid: "do", "handle", "process", "manage", "ensure things are OK".

## Formatting
- UI elements in **bold**, exactly as on screen.
- Values the user types in `code` style.
- Menu paths with ›: **Export › Booking › New**.
- Notes and warnings as one-line callouts: **Note:** / **Warning:**.

## Screenshot references
Write "Fig. n: [screen name]" in the Screenshot column when a screenshot was described; list screens with no screenshot under Needs input as "screens to capture".

## Detail levels
| Level | Use | Step granularity |
|---|---|---|
| Trainee | New joiners, audits | One click per step, every expected result |
| Standard (default) | Operators | One UI action per step |
| Condensed | Experts, quick reference | One screen per step |
